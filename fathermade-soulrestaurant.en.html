Main Logic & Pipeline

Built the foundation for board generation, the game's main logic, using Photoshop scripts, PSD Importer and 2D Tilemap.

Design Requirements

  • To avoid managing many images in a single Sprite Sheet and to ease collaboration with outsourced artists, keep each icon image as its own Photoshop file
  • Photoshop effects must carry over without loss
  • Avoid duplicate resources to keep commits lightweight
  • Easily add and edit item icons even after launch, without compromising service stability
  • Easily create and edit boards using items and slots

Pipeline

  1. Resource placement (Art) — After creating icons, place the files in designated folders following the naming rules
  2. Photoshop script (All) — Reads icons from relative paths within the project and regenerates them as Linked Layers
  3. PSD Importer (Automatic) — Automatically generates the Sprite Atlas and Tilemap Assets
  4. Tile Palette (Game Design) — Streamlines board creation with the 2D Tile Palette tool

Each cell of the board maps to a single Tilemap grid cell painted with the Tile Palette. Using the Tile Palette's custom brush feature, I built an environment where boards are made by stamping prefabs directly onto the grid while seeing the result, while keeping Unity's standard tools such as the Move Tool fully usable, removing as many workflow constraints as possible.

Out-game · Restaurant

To develop the restaurant, an out-game element, I built a 2.5D world level design tool that places 2D images in 3D space while keeping the correct sorting order.

Although the engine provides features such as Sorting Layer, Sorting Order and Sorting Group, I built a tool that slices and places textures so that images render in the order they appear as placed, improving efficiency for artists and designers and reducing human error.

Workflow

  1. Texture slicing — An editor script automatically slices textures into Multiple Sprites based on camera size, Pixel Reference, world grid size settings and camera angle
  2. Pivot setup — In an extended Sprite Editor tool, set each slice's floor point as its pivot using a GUI tool
  3. Placement — Place images in the Scene View using Handles

Spine animations and regular images placed together in the 2.5D world while sorting front-to-back naturally. Each image is actually finely sliced along the vertical axis, but carefully calculated placement logic keeps the seams between slices invisible to players, while the development environment also looks identical to the actual game screen. Artists can also work on the Default Layer at Sorting Order 0 without having to learn Sorting Layer, Sorting Order or Sorting Group, making for an artist-friendly environment.

Maintenance

Debug-Friendly Development Environment

Building on an understanding of Unity's serialization system, I structured code and implemented systems so that each field's data can be easily inspected in real time in the Editor, without affecting player builds.

  • No impact on performance, memory or build size of player builds
  • Inspect each field's data in real time in the Editor
  • Leveraged built-in engine systems as much as possible to reduce the maintenance burden of writing a custom Editor script for every feature

Asset Management Tool

  • Built a tool that traverses key assets and prefabs to look up References in use and key field values
  • Enables identifying texture files in use, looking up localization keys, handling Missing Components, understanding UI structure and finding effect objects, among others

Optimization

  • Avoided Animator for UI performance and implemented Tweening Animation
  • UI that needs Animator for ease of authoring is split into separate canvases as needed to minimize the scope of Canvas rebuilds
  • Minimized MonoBehaviour usage
  • Manually controlled physics world Update timing
  • Simplified the Hierarchy of key objects
